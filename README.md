# TimeNote

专为**周期日记（Daily Notes）**设计的时间轴与全周期日历视图插件。同一个仓库维护三个宿主版本，共用一份渲染引擎、解析规则与远程聚合逻辑。

> 本页主体是 **Obsidian 版**的使用说明；思源 / Blinko 版见下一节。

---

## 🎯 核心特性

1. **直接以日记为唯一数据源**：
   - 不改变笔记习惯，无需将任务拆成独立 Markdown 文件；
   - 自动识别日记行内的 `14:00`、`14:00:31` 或 `14:00-15:30` 时间范围，并精准排布在时间网格上；
   - 时间块按起止时间绘制有高度的卡片，仅在真正重叠时左右分列，并显示时长徽标；
   - **单时间点记录画成一条对应时刻的线**，不扩展成任务 / 时间块，整条拖动只改时刻、不能拉伸成块；可从工具栏 / 设置切换「新增：时间点」直接创建；
   - **记录可以拖到别的日期列**：块（拖中部）与时间点线横向拖到当前视图的另一天，即把该行（含缩进子项）搬到那天的日记；
   - 「当前时间」指示线横跨网格并显示 `HH:mm`，按分钟定位、30 秒自动刷新，只在所显示日期包含今天时出现。
2. **全天待办分列垂直对齐**：
   - 无具体时间的行或任务，自动归入该日期的**「全天栏」**；
   - **严格按具体各天分列展示**，各归各天，不会混在一起；
   - 顶部日期栏、全天栏与下方时间轴列完全垂直对齐。
3. **列表主子项智能收纳**：
   - 严格只记录**主列表项**，缩进的子列表（带空格或Tab的子待办/要点）自动附属于父项；
   - 卡片上带有子项徽章（如 `▾3`），点击即可在弹窗中查阅所有子项内容，并支持一键定位原笔记行。
4. **双轨翻页导航**：
   - `⏮ 上周期` / `下周期 ⏭`：随当前视图按对应周期大跨度切换（1天 / 3天 / 1周 / 1月 / 1季度 / 1年）；
   - `◀ -1天` / `+1天 ▶`：精确按单日平滑推移；
   - `今天`：一键回归当前日期。
5. **双向无缝联动**：
   - 在日历界面上直接点击复选框，**实时回写并切换日记原文件中的 `[ ]` ↔ `[x]`**；
   - 点击条目卡片，**直接打开原日记并精确定位高亮对应行**；
   - 点击 `ALL DAY` 行上方的**日期标题**（日 / 3天 / 周视图，块布局与紧凑流通用；时间线视图的「打开日记 ↗」同效），**直接打开当天日记**；该日尚无日记时按 `SpiralNotes/YYYY/Daily/MM/YYYY-MM-DD.md` 自动创建再打开。下钻到日视图仍用顶部「日」标签；
   - 点击日历空白时间槽或「+ 记一条」，快速向当日日记插入新记录。

## 📅 七大视图模式

| 视图 | 标识 | 说明 |
| :--- | :--- | :--- |
| **日视图** | `Day` | 聚焦单日，全宽大卡片排布，直观呈现每小时记录与任务执行情况。 |
| **3天视图** | `3-Day` | 连续 3 天时间网格，适合短期排程与跨日任务对比规划。 |
| **周视图** | `Week` | 周一至周日 7 天纵览，上方各天全天待办独立分列，红线实时指示当前时刻。 |
| **月视图** | `Month` | 经典月历网格，带每日记录数量徽标，点击任意日期即可进入日视图。 |
| **季度视图** | `Quarter` | 当季 3 个月全景看板，展示季度累计条目、待办达成率、灵感统计与 3 月迷你日历。 |
| **年度视图** | `Year` | 全年 12 个月时间足迹全景，采用 GitHub 风格 5 级活跃度热力色块与全年统计。 |
| **时间线** | `Timeline` | 单日流水账瀑布流，带时间圆点轴线，支持子项层级预览与快速跳回原日记。 |

## 🧩 三个宿主版本（DEC-032）

| 宿主 | 入口 / 产物 | 本地记录存哪 | 状态 |
| :--- | :--- | :--- | :--- |
| **Obsidian** | 仓库根三件套 / `timenote-<version>.zip` | vault 里的 `SpiralNotes/YYYY/Daily/MM/YYYY-MM-DD.md` | ✅ 已发布（v1.1.2） |
| **思源笔记** | `apps/siyuan/` → `dist/siyuan/package.zip` | 思源原生每日笔记文档的**块**（内核 `/api/*`） | ⚠️ 已实现，**尚未真机验证** |
| **Blinko** | `apps/blinko/` → `dist/blinko/release.zip` | Blinko 原生 **note**（`window.Blinko.api` tRPC） | ⚠️ 已实现，**尚未真机验证** |

三个版本共用 `ui/view.ts` 渲染引擎、`sources/daily.ts` 的解析与回写、`styles.css`，以及 memos / 远程 Blinko 的只读聚合（60 秒区间缓存、单源失败不打断日历）。新宿主把原生数据映射成**虚拟 markdown 文件**再接进 `DailySource`，所以拖拽改时间、横向跨天搬移、点击勾选待办的行为与 Obsidian 版一致；写回只动变化的那一个块 / note，保留实体 id。

**构建**：`npm run build:plugins`（独立于 `npm run build`，Obsidian `main.js` 逐字节不变）。`dist/` 已 gitignore，两个 zip 只在本机生成、不入库。

**安装与验收**：见 [思源版 README](apps/siyuan/README.zh-CN.md) / [Blinko 版 README](apps/blinko/README_zh.md)，两份都写清了「数据存在哪里」「已知边界」「验收清单」。首版**未在真机验证** —— 本机没有思源 / Blinko 实例，实现依据是官方源码 + 离线模拟测试（含加载期冒烟），装完请按清单逐项试一遍。

**发布链路**：从 `v1.1.3-beta.1` 起，`.github/workflows/release.yml` 在每次 `v*` tag 发版时同时跑 `npm run build:plugins`，Release 共挂 6 个资产：`manifest.json` / `main.js` / `styles.css` / `timenote-<version>.zip`（Obsidian）+ `package.zip`（思源）+ `release.zip`（Blinko）。Blinko 安装器要求资产名固定为 `release.zip`；思源首版不走集市（集市要求插件名 == 仓库名），需下载 `package.zip` 手动解压。**预发布 tag 带后缀**（如 `v1.1.3-beta.1`），资产路径是 `releases/download/v1.1.3-beta.1/release.zip`；安装器一般只读 Latest，预发布阶段请手动下载。打包失败会让整个 Release 变红 —— 宁可不发，不发缺件的包。

## 🚀 快速上手

1. **安装**：从 [Releases](https://github.com/AIDockerCloud/TimeNote/releases) 下载最新的 `timenote-<version>.zip`，解压到 `<vault>/.obsidian/plugins/timenote/`（zip 根目录就是三件套，不要再套一层文件夹）；也可以手动把 `manifest.json`、`main.js`、`styles.css` 放进去。重启 Obsidian 并在「社区插件」中启用 **TimeNote**。
2. 在 Obsidian 左侧功能区点击时钟日历图标 `calendar-clock`，或在命令面板输入：
   `TimeNote: 打开时间笔记日历视图`
3. 在插件设置中可配置：
   - 周期笔记根目录（默认 `SpiralNotes`，自动支持 `SpiralNotes/YYYY/Daily/MM/YYYY-MM-DD.md` 结构）；
   - 是否聚合展示 `Blinko` 微闪念；
   - 默认视图模式、时间轴起止时间（默认 00:00 - 24:00 全天，可按作息收窄，如 06:00 - 24:00）、一周起始日等；
   - 时间网格布局（块布局 / 紧凑流）、新建记录默认类型（时间块 / 时间点，**默认时间点**）、新建时间块默认时长、每小时槽高（默认 52px，也是自适应轴的行高基准）、自适应时间轴开关、ALL DAY 行高度（默认 36px）。
   - **快速记录默认插入标题**：直接写带 `#` 的标题，如 `## 灵感闪念` 或 `### 随手记`，即可同时指定层级与标题名（不写 `#` 时按二级处理）。新建日记按该层级建节；已有日记里若存在同名标题（任意层级）就沿用那一节，不会重复建标题。旧配置里的纯文本值（如 `灵感闪念`）自动按 `## 灵感闪念` 兼容。
   - **日记模板文件**：**留空（默认）= 自动复用 Obsidian「日记」核心插件里「模板文件位置」配置的模板**；填 vault 内路径（如 `SpiralNotes/Templates/Daily.md`）= 用插件自己的模板；填 `off` = 不用模板，保持内置的「`# 日期` + 快速记录标题」三行结构。仅影响**新建**日记，已有日记一个字都不改。

**日记模板怎么用**：新建日记时（点空白日期标题、或 QuickAdd 当天还没有日记）会先读模板内容、替换变量，再写入 `<周期笔记根目录>/YYYY/Daily/MM/YYYY-MM-DD.md`。支持的变量与 Obsidian 核心模板插件一致：

| 变量 | 展开为 |
|---|---|
| `{{date}}` / `{{title}}` | 按 Obsidian 日记插件的「日期格式」展开（⚠️ 若格式里含目录如 `YYYY/[Daily]/MM/YYYY-MM-DD`，裸 `{{date}}` 会得到 `2026/Daily/11/2026-11-12`，写标题请用 `{{date:YYYY-MM-DD}}`） |
| `{{time}}` | 当前时间 `HH:mm` |
| `{{date:FORMAT}}` / `{{time:FORMAT}}` | 当天 / 当前时刻按指定 moment 格式展开，支持偏移如 `{{date+1d:YYYY-MM-DD}}`、`{{date-1w:YYYY/MM/DD}}` |
| `{{yesterday}}` / `{{tomorrow}}` | 相邻日期，按日记插件的「日期格式」展开 |

模板里若已含「快速记录默认插入标题」那一节（例如 `## 灵感闪念`），新记录直接插到该节标题下、不会重复建节；没有则在文末补一节。有模板时**不再**自动加 `# 日期` 一级标题（与 Obsidian 一致，避免破坏模板自身的标题结构）。模板文件读不到、内容为空或填了 `off` 时，静默回退到内置结构并在控制台给出提示。

> ⚠️ 已知取舍：TimeNote 会把日记里所有顶层 `- [ ]` 复选框行解析成 ALL DAY 待办。如果模板里有「习惯打卡」之类的固定待办清单，它们会一并出现在日历里；解析器目前也不跳过 fenced code block 内部的行。本轮按用户决定暂不处理，需要时再开独立 ADR。

## 🧱 时间块记录

时间块用来记录「一段时间做了什么」。它**不是新视图模式**，而是融入日 / 3天 / 周视图的共享渲染层（DEC-007）。

**写法**（仍是普通日记行，日记是唯一数据源）：

```markdown
- 14:00-15:30 写周报 #工作
- 09:00 站会 30m
- 10:00 ~ 11:00 需求评审
```

也支持 `14:00至15:00`、`14:00/15:00`；单时间点后写 `30m` / `1h` / `45min` 可指定时长。**只有 `HH:mm`、没有结束时间也没有时长标签的记录是「时间点」，不是时间块** —— 见下一节。

### 时间点记录（线，不是块）

只写一个时刻的日记行不会被扩展成 30 分钟的任务块：

```markdown
- 09:23 到公司
- 12:05 午饭 #生活
```

在块布局里它是一条**精确落在 `09:23` 位置**的水平线，圆点标出起点，信息（时刻 + 内容 + 标签）排在**线下**；15 分钟内的多条点记录归为一簇，标签逐行错开，不会互相盖住。线沿用当天自动分配的颜色，与时间块同色系但形态完全不同。

- **可拖动**：整条线上下拖动改时刻（1 分钟吸附），松手只回写行首那个 `HH:mm`，**绝不生成结束时间或范围**；其余文本、缩进、复选框、标签原样保留。
- **可跨天**：横向拖到当前视图的另一天，整条记录（含缩进子项）会被搬到那天的日记，行首仍只写一个时刻。
- **不可拉伸**：没有上下边缘命中区、没有把手，也没有「把点拖成块」的暗示；Blinko 等外部来源只读不可拖（仍可点击跳转原笔记）。
- 时间线视图与快速记录弹窗也不再给时间点补一句虚构的 `30m`；紧凑流计算空闲段时同样不再把点当 30 分钟块。
- 样式层已预留 `.timenote-point-line.is-above`（信息改到线上），默认线下；如需在设置页开放切换再另行提供。

**添加**：默认记**时间点**。工具栏「**新增：时间块 / 时间点**」按钮、设置页「新建记录默认类型」按钮、快速记录弹窗里的「记录类型」按钮，**都是单击直接切换**，不用点开下拉再选一次。工具栏「+ 记一条」与紧凑流的空闲段点击同样跟随这个类型。工具栏「+ 记一条」默认记**今天**（不受视图翻页影响）；点日历空白槽仍按所点的那一天记。旧 `data.json` 里显式存了「时间块」的用户仍沿用时间块。

- **时间块**：在空白时间槽按住上下拖动，虚线预览块实时显示 `起 - 止 · 时长`，松手即打开快速记录并预填该范围；吸附 15 分钟、最短 15 分钟。不拖动直接点一下，按点击位置吸附 30 分钟并预填默认时长。
- **时间点**：在时间点模式下（默认），在空白槽单击或上下拖动只定一个时刻（虚线预览线显示 `HH:mm`，15 分钟吸附），松手打开快速记录，**结束时间输入框被禁用且留空**，保存后写入 `- 09:23 到公司` 这样的单时间行 —— 在日历上是精确时刻的一条线，不是块、不带复选框。**按住 Alt 点空白槽可临时切到另一种类型**（默认时间点时临时记时间块，默认时间块时临时记时间点），不必切换按钮。
- 时间块模式下也可在「+ 记一条」中手填开始 / 结束时间，弹窗实时显示时长。结束必须晚于开始，一期不支持跨零点。

**创建框：标题与正文（DEC-033）**：快速记录弹窗把内容拆成两个字段 —— **标题必填、单行**（写进带时间前缀的主行；标题框里按回车直接保存），**正文选填、可多行**（`Ctrl+Enter` 保存）。正文每行落盘时前面加一个 Tab，成为标题记录的缩进子项，日历里点子项徽章就能看到；空行会被忽略，正文里写 `## 小标题`、代码块或 `%%` 也不会被误当成新章节或 ALL DAY 任务。

```markdown
- 14:00-15:30 写周报 #工作
	先列大纲
	补充数据
```

**创建预览不再消失**：横拖选好范围松手后，日历上那块会变成「待创建」块**留在原处**（底色更实的虚线块），弹窗里改起止时间、切换时间点 / 时间块、输入标题时，它的位置、高度与文字实时跟着变；改了日期还会挪到对应日期列（当前视图看不到那天就先隐藏）。取消、`Esc`、点遮罩或保存成功才移除 —— 保存后由真实记录接替。工具栏「+ 记一条」和紧凑流空隙没有对应的拖拽区域，仍是无预览的旧行为。

**展示**：块的上沿对齐开始时间、下沿对齐结束时间，**高度恒等于它在时间轴上的跨度**（与整点刻度严格一致）；只在真正重叠时才左右分列，不重叠的块占满整列；卡片显示起止时间与时长（时间线视图对块显示时长、对时间点只显示时刻）。

**自适应时间轴（内容定高）**：默认开启。整点行不再固定等高，**行高由该小时的内容量决定** —— 没有记录的小时压到最扁（约为槽高的三分之一，最低 16px），有记录的小时按条目内容需要的高度撑开（标题最多折 6 行）。块的上沿对齐开始时间、下沿对齐结束时间，高度恒等于自身的时间跨度，所以**内容多的时段块更高，内容少的时段块更矮**，而不会出现「块只占时间段一小截」的错位。同一小时里先后发生的多条记录上下叠放、同时发生的左右并排，块永远不会挤在一起。整条轴的高度随内容伸缩：内容少的一天更紧凑，内容多的一天更长、可滚动；内容不足一屏时等比放大行距（最多 1.5 倍）。设置里关掉「自适应时间轴」即回到每小时严格等距的传统样式。

> 块的上下沿始终对应真实起止时刻；一条时长很长但只有一行字的记录，块会跟着变高（下方留白），因为它的时间范围就是这么长。

**调节**：拖动已有块的**上/下边缘**改起止时间（块的下沿就是结束时刻），拖动**块中部**整体平移；松手后直接回写日记该行的时间前缀（其余文本、标签、复选框原样保留），并弹出 Notice 告知新范围。**没有把手**：上下边缘本身就是命中区，按块高的 1/3 自适应（2–9px），哪怕最短的 15 分钟块也能改边界；光标靠近边缘变 `ns-resize`、中部为 `grab`，这就是唯一的提示。拖拽结果会被夹在可见时间轴内，不会把块拖出画面。**时间点线则是整条上下拖动只改时刻**（1 分钟吸附），没有边缘、不能拉伸成块，详见上一节；两类拖拽各自回写，互不转换。

**跨天拖动**：在日 / 3天 / 周视图里，拖动**块的中部**或**整条时间点线**时横向移到另一个日期列，**释放前**目标列会整体高亮并在列顶显示「松手 → YYYY-MM-DD」，块 meta / 时间胶囊也显示完整落点日期；横拖了却显示 `→ ?` 表示这一刻没识别出落点（可据此排障）。松手即把这条记录（连同紧跟其后的缩进子项）搬到那一天的日记 —— 先按同样的插入规则写进目标日记（不存在则自动创建），再从原日记删掉那一行。行首时间按本次拖动结果回写，**块仍是范围、点仍是单时间**，两篇日记的其余内容与顺序一律不动。边界：只认当前视图里真实存在的日期列（落在刻度列 / 视图外不跨天，想搬到范围外的日期请先翻页）；拖块的上下边缘改起止时不跨天；Blinko 等外部来源只读、不可跨天；日记在解析后被外部改动导致行号对不上时整笔操作会拒绝并提示，不会误删内容。跨零点范围（`23:00-01:00`）仍不支持。

**显示细节**：整张表是「一整张表格」—— 表头、`ALL DAY` 行、整点网格同底色、同一套竖线，去掉文字后看不出哪一行特殊；时间刻度用 600 字重正文色，当前小时染主色；时间块是实色卡片（20% 底 / 42% 边 / 4px 左色条），文字始终用正文色，不会被底色遮住；**同一天的时间块自动使用互不相同的颜色**（8 色调色板，按天独立分配、重渲染不跳色，新块自动拿到当天未用色），想固定某个颜色可在日记行里写 `#color/blue` 或 `#色/蓝`（也支持 `#color/#7c5cff` 自定义色值）。块内只写标题与起止时刻，时长落在右下角。设置里可调「每小时槽高」（28–96px，默认 52）控制时间块松紧；`ALL DAY` 行高度可**直接拖动该行与网格之间的分隔条**调节（32–320px，默认 36），也可在设置里改；「当前时间」主色指示线横跨网格并在左侧显示 `HH:mm`，每 30 秒刷新，当前时刻不在可见范围内时自动隐藏。网格顶部不留余量（`ALL DAY` 行与第一个整点之间没有任何空行），底部留 14px 让结束时刻的标签完整显示、最后一行贴近底部。

**布局切换**：工具栏「块布局 / 紧凑流」随时切换，设置里可改默认值（默认块布局）与新建时间块默认时长（默认 1 小时）。紧凑流是原有的折叠空闲时段、按行展示模式（紧凑流不画当前时间线，时间轴已被压缩折叠）。

> 时间块只做**实际记录**：不做计划排程、容量规划或计时器；勾选「作为任务待办」仍是原有功能。

## 🔖 版本号

`manifest.json`、`package.json`、`versions.json` 三处版本保持一致，**每次提交 patch +1**（`1.0.1` → `1.0.2`）：

```bash
npm run bump          # 1.0.1 → 1.0.2
npm run build         # 产物 main.js 必须一起重建
```

`versions.json` 记录 版本 → `minAppVersion` 映射，是社区插件发布的必需文件。

**发版靠 tag**：构建、打包、建 Release 全部由 GitHub Actions（`.github/workflows/release.yml`）完成。

```bash
# 正式版（本地终端，签名 tag）
git tag -s v1.1.3 -m "v1.1.3"
git push origin v1.1.3

# 预发布（带后缀 → GitHub 自动标 Pre-release、不抢 Latest）
git tag -s v1.1.3-beta.1 -m "v1.1.3-beta.1"
git push origin v1.1.3-beta.1
```

tag 去掉 `v` 后的**主版本段**必须与 `manifest.json` 的 `version` 完全一致，否则 workflow 直接失败（防版本漂移）。**预发布用带后缀的 tag**（如 `v1.1.3-beta.1`，`manifest.json` 仍写 `1.1.3`），验证通过后再推正式的 `v1.1.3`。Release 产物 = `manifest.json` + `main.js` + `styles.css` + `timenote-<version>.zip` + `package.zip`（思源）+ `release.zip`（Blinko）；Obsidian zip 内不套目录，可直接解压进插件目录或交给 BRAT。

## 🛠 本地开发

源码是 `main.ts`，`main.js` 为 esbuild 生成产物（仍入库，便于零构建安装）。**请勿直接编辑 `main.js`**。

```bash
npm install        # 首次拉取 devDependencies
npm run dev        # watch 模式，改动 main.ts 自动重建 main.js
npm run build      # tsc 类型检查 + 生产构建
npm run typecheck  # 仅类型检查
npm run check      # 类型检查 + PCMP 合规校验
npm run pack       # 打包三件套 → dist/timenote-<version>.zip（不构建，先 build）
npm run dist       # build + pack 一步到位
npm run build:plugins  # 思源 / Blinko 两个插件包 → dist/siyuan/、dist/blinko/
npm test           # 18 套 951 项断言（含 test:platforms 171 项、test:quick-add 24 项）
```

`npm run build:plugins` 不并进 `npm run build`，避免每次主构建都重打两个 zip；
构建后建议 `git diff --stat -- main.js` 确认 Obsidian 产物没被带改。

构建链：TypeScript 7 + esbuild 0.28（CJS / browser，`obsidian` 保持 external，产物不压缩便于审阅）。改完代码先 `npm run build`，确保 `main.js` 与 `main.ts` 同步再提交。
